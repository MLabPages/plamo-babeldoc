# 翻訳受付と中止の安定化

## 発見した問題と変更

- 同じ論文・エンジンへの同時依頼で重複したキュー項目が作成されるため、受付判定と登録をロック内で実行する。
- 中止・再試行を区別する処理IDを保存する。古いキュー項目や進捗・例外・完了通知は新しい試行を上書きしない。
- モデル起動後とワーカー作成直前に中止状態を確認する。読書モード生成中の中止も完了に戻さない。
- PDFが残っていてもワーカーの終了コードが非ゼロ、または明示的なエラーがあれば失敗として扱う。
- PDFをメモリ上で検証してからライブラリに登録する。破損・暗号化・ページなしの入力は拒否する。入力エラーはHTTP 400で返す。

## 検証

- `python -m unittest discover -s tests -p test_jobs.py -v`: 12件。
- `python tests/test_references.py`: 既存10件。
- 一時フォルダーと生成した1ページPDFを使用。翻訳プロセスとモデル起動はテスト用の代替実装で検証する。
- HTTP受付は実際のローカルサーバーで検証する。クラウドAPIへ論文やテスト本文を送信しない。
- 実際のモデルによる翻訳品質・速度の再評価や、開いているアプリの再起動は今回行わない。変更の反映にはアプリの再起動が必要。

## 範囲と制約

画面構成・翻訳エンジン・既存論文データは変更しない。モデルの読み込みそのものは中止ボタンで即時停止しないが、中止された依頼から翻訳ワーカーを起動しない。
